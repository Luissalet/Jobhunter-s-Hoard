# Direction: expediente profesional

Mode: Operate. Code-first explicitly chosen by the user. The user delegates structure and visual direction.

Grounded candidates considered: correspondence inbox; editorial ledger; recruitment desk; career notebook; calendar agenda; document library; professional dossier (assigned index 7, seed d6a1cbbf).

Commitment: a professional dossier, a stable left index and a spacious working page, with precise table rows, warm paper neutrals, forest ink for action and restrained status tones. Humanist sans typography, visible labels, dates and evidence. The first view proves what is waiting, what was submitted, and what the assistant needs. No fictitious applications or metrics. The empty view offers direct setup, adding a job and importing the user's sheet.

Primary path: profile/context → capture job → read and prepare → approve or use configured automatic mode → browser attempt → observed result. Settings and MCP connection are separate destinations; provider settings are optional for an external assistant.

Challenger disposition: ASCII scene and phosphor terminal declined because a fixed character grid and camera/command navigation impede long editable application forms. Keep their precision in table alignment and visible operation states, without decorative terminal styling. Caption-field direction declined because overlapping caption hierarchy obscures job comparisons; keep decisive hierarchy and distinct status text. No raster assets needed for this operative interface.

Responsive: side index becomes a compact top navigation on mobile, table becomes stacked job rows, split forms become single-column, detail takes the viewport. Focus rings and state changes remain visible. No decorative motion; respect reduced-motion. Risk: long personal forms; mitigate with section tabs, inline helper copy and a persistent save action.

## Operational surface extension · September 2026

Inherit the established Operate dossier, paper surfaces and forest actions. These surfaces extend the existing working page and introduce no replacement identity.

- Candidaturas: combine exact status and work-mode filters with search; retain ordering by status, modality and submission date on mobile. Separate opening the dossier from inline state editing and selection. Bulk changes target selected visible rows and retain failed rows for retry. Submission dates remain readable on mobile; missing dates stay unknown.
- Agenda: expose sent, answered and interview-stage applications without a next review or future interview in Sin próxima acción. Scheduling a review does not require inventing a submission date. Keep drafting and sending distinct.
- Resultados: distinguish current-state distributions from historical milestones. Responses include rejections; interviews and offers use current status and recorded history. Undated submissions count in totals but not the eight-week activity display. Show modality and source comparisons with textual counts.
- Mi contexto / Respuestas: search existing questions and answers, copy, and edit in place. Preserve real text, line breaks and the context save boundary; no fixed example count or fabricated answers.
- Mi contexto / Cartas: a library per context with Spanish/English metadata, editable base text and supported variables `{{puesto}}` and `{{empresa}}`. Separate the read-only prepared preview from the stored template. Puesto/Empresa only personalize the preview; Guardar cambios persists the library. No private letter content belongs in design examples.
- Detalle / Oferta: editable offer facts and actual submission date, with local Guardar datos and Cancelar actions inside the existing scrollable dossier.
